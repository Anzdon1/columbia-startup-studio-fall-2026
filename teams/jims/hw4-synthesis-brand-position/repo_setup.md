## How we work

- Framework: Feature Forge. Follow brief, plan, build, verify, ship, and learn for each feature.
- Keep changes focused and make small commits.
- Ask before adding a new library, external service, or source of apartment data.
- Do not claim a listing is verified, safe, complete, or objectively best without evidence.
- Keep each change focused on one feature or bug.
- Read `docs/brand_position.md` and `docs/style_guide.md` before changing copy or visual design.
- Ask before adding a dependency, external API, paid service, or new source of apartment data.
- Reuse existing patterns before adding a new abstraction or component.
- If you want to add a new component or method ASK FIRST
- Add or update tests for behavior changes, then run the relevant checks before committing.
- Do not change secrets, deployment settings, or database schemas without approval.
- Clearly label missing, unverified, or user-provided apartment information.
- Keep accessibility in mind: readable contrast, keyboard access, labels, and mobile-friendly controls.
- If this is your first time making changes to this project, do i throrough read through of everything with the goal being to understand what has already been built, what is currently being built, and how each feature and component works in tandem with others
- Do not attempt to override user information without prior approval
