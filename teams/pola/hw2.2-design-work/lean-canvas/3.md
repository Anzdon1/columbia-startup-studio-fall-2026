# Lean Startup Canvas

## 1. Problem

1. Students with demanding workloads must carry relatively heavy laptops, chargers, adapters, external drives, batteries, or specialized hardware across campus.
2. High-performance workloads such as compilation, 3D rendering, CAD, simulation, ML, video editing, and game development often conflict with the portability and battery life of lightweight laptops.
3. Existing campus computer labs interrupt workflow because students must log in, reconfigure software, sync files, restore projects, and recreate their workspace each time.

**Existing alternatives:**
- Powerful personal laptops/workstations
- Remote desktop into a personal machine
- University computer labs
- Cloud VMs
- VDI
- SSH into university servers
- Carrying external SSDs
- Working only where a personal workstation is available

**Assumptions to validate:**
- How painful mobility actually is compared with these existing alternatives
- How frequently students currently abandon or delay work because their hardware is unavailable

## 3. Unique Value Proposition

> **"Your workstation follows you across campus—even when the computer doesn't."**

Students get lightweight mobility while retaining access to:
- Powerful hardware
- Their software environment
- Files
- Settings
- Credentials
- Development tools
- Active workspace state

For universities, the system provides expensive computing capacity as shared infrastructure rather than requiring every student or department to maintain powerful individual machines.

**High-level concept:**

> A campus version of hot-desking, but for complete personal computing environments.

**Assumption to validate:**
- Whether instant environment continuity provides enough additional value over conventional VDI, cloud desktops, or remote desktop systems

---

## 4. Solution

Deploy standardized high-performance computing stations or docks throughout high-demand campus locations.

Students authenticate through university SSO and load a persistent workspace stored either:
- In a secure cloud-based profile, or
- On an encrypted lightweight personal module

The system restores:
- Files
- Applications
- Preferences
- Development environments
- Mounted storage
- Credentials
- Optionally, active application/session state

Different workstation tiers could support:
- General-purpose computing
- GPU workloads
- CAD and architecture
- Media production
- Software development
- Specialized departmental applications

Optional powered carts or mobile docking systems could support:
- GPUs
- AV equipment
- Robotics hardware
- Specialized lab devices
- Other hardware that still needs to move physically

### MVP

Do **not** initially build a campus-wide network.

Start with:
- 5–10 identical workstations
- 2 campus buildings
- 1–2 high-value workflows, such as:
  - CS/software-development environments
  - GPU workloads

Measure whether students actually move between stations and repeatedly resume their environments.

**Assumptions to validate:**
- Session migration speed
- Software licensing compatibility
- Security
- Application portability
- Whether "resume anywhere" can actually feel near-instant

## 6. Revenue Streams

The most plausible primary business model is **institutional licensing**, rather than direct student subscriptions.

Possible revenue streams:

- Annual per-station software/platform licensing
- Annual university-wide licensing based on active users
- Hardware + deployment packages
- Managed infrastructure contracts
- Technical support contracts
- Premium GPU or compute capacity purchased by departments
- Hardware leasing
- Integration and migration services
- Maintenance contracts

An alternative model is for universities to own and operate the hardware while the startup provides only:
- Workspace orchestration
- Session portability
- Identity integration
- Management software

Possible secondary revenue:

- Student-paid premium GPU hours
- Additional storage
- Specialized compute access

These should probably not be assumed to be the core revenue source.

**Assumption to validate:**
- Whether universities are willing to pay for this instead of adapting existing VDI, cloud, or computer-lab infrastructure

## 8. Key Metrics

### Usage metrics

- Weekly active users
- Sessions per user per week
- Workstation utilization rate
- Peak utilization rate
- Average session length

### Mobility metrics

- Percentage of sessions resumed on another machine
- Number of different stations used per user
- Number of buildings used per student
- Frequency of cross-location workspace continuation

### User experience metrics

- Median login-to-workspace-ready time
- Session resume latency
- Failed session rate
- Authentication failure rate
- Support tickets per 100 sessions
- User satisfaction
- Net Promoter Score

### Business/value metrics

- Cost per active student
- Cost per workstation-hour
- Cost compared with conventional labs
- Reduction in idle departmental computers
- Reduction in demand for personal high-performance hardware
- Percentage of pilot users returning after initial use
- Department renewal rate

### Critical MVP metric

> **Percentage of pilot users who voluntarily use the system repeatedly after the novelty period ends.**

A strong signal would be users choosing the shared stations even when their own laptop remains available.

## 9. Unfair Advantage

Initially, there may be **no strong unfair advantage**.

Existing technologies already solve pieces of the problem:
- VDI
- Cloud desktops
- University computer labs
- Remote workstations
- Containers
- Roaming user profiles

Potential long-term defensibility could come from:

- Deep integration with university identity systems
- Integration with course enrollment and software entitlement
- Integration with campus room and lab infrastructure
- A portable application/session layer optimized for local campus hardware
- Faster state migration than conventional VDI
- Hardware-aware workload orchestration
- Proprietary workstation placement and utilization data
- Cross-campus infrastructure standards
- Partnerships with universities
- Partnerships with workstation manufacturers
- Integration with software licensing systems
- Network effects from a common campus-computing ecosystem

**Assumptions to validate:**
- Whether there is genuinely differentiated technology
- Whether the product is meaningfully better than packaging existing VDI, container, and device-management technologies into a more convenient interface

# Highest-Risk Assumptions to Validate First

1. **The pain is severe enough.**  
   Students may complain about heavy laptops without being willing to change their computing habits.

2. **Students want workstation continuity more than device ownership.**  
   Many students may still strongly prefer having their own computer immediately available.

3. **Shared stations are available when students need them.**  
   If stations are regularly occupied, the value proposition deteriorates quickly.

4. **Workspace restoration is fast enough.**  
   "Sit down and continue immediately" likely needs to mean tens of seconds rather than several minutes.

5. **Applications move cleanly between machines.**  
   CAD software, Adobe products, game engines, GPU environments, local VMs, plugins, and license managers may complicate portability.

6. **Universities see economic value.**  
   The platform must be cheaper, easier to manage, or offer meaningfully better utilization than current labs, VDI, or cloud desktops.

7. **Security is manageable.**  
   Shared machines handling personal credentials, source code, research data, and academic files create substantial security requirements.

8. **Demand is high enough to justify physical infrastructure.**  
   A high-end workstation operating at low utilization may have poor economics.

9. **The physical personal module is actually necessary.**  
   A cloud-backed identity and workspace profile may prove much simpler and more attractive than requiring students to carry another device.

# Core Lean Startup Hypothesis

The key hypothesis is not merely:

> "Students dislike carrying heavy computers."

The stronger hypothesis is:

> **Students with demanding computing workloads experience enough friction moving their computing environment between campus locations that they will repeatedly choose shared high-performance workstations when their workspace follows them automatically.**

The MVP should be designed primarily to test this hypothesis.
