# Lean Canvases

## C3 — Two-Minute Reunion

| Canvas box | Draft |
| --- | --- |
| Problem | Long homecoming reports demand more attention than busy owners will regularly give. When owners miss what changed, continuity weakens and visits start to feel interchangeable. |
| Customer segments | Claude Code–using students and young professionals interested in Daycare but unwilling to read long reports. Early adopters are people who have already accumulated reports or memories. |
| Unique value proposition | **Catch up with your Claude in two minutes and leave knowing what changed.** |
| Solution | Show one key story, one changed memory, and one question from the agent, with optional links to the full report and evidence. |
| Channels | Existing Daycare users, campus AI and coding clubs, Claude communities, shared sample reunion cards, and referrals. |
| Revenue streams | Free retention experiment first; later test inclusion in a Daycare membership or continuity tier. |
| Cost structure | Summary generation, interface work, report and memory storage, evidence links, quality evaluation, and support. |
| Key metrics | Reunion completion, reply rate, evidence drill-down, another visit within seven days, four-week retention, and unsupported-summary rate. |
| Unfair advantage | A growing owner-specific interaction and memory history could make each reunion more personal; this advantage is not yet proven. |

**Main assumption:** reports go unread because catching up takes too much effort, rather than because the underlying visits are not interesting.

**First test:** give 10 target users both a full report and a manually created reunion card, then measure completion, comprehension, replies, and follow-up behavior.

## B2 — Allowance Guardrails

| Canvas box | Draft |
| --- | --- |
| Problem | Daycare leisure and important Claude Code work use the same limited subscription allowance. Owners may avoid a visit because a percentage choice does not guarantee enough capacity remains for later work. |
| Customer segments | Apple Silicon Claude Pro or Max users who rely on Claude Code for coursework, freelance work, side projects, or other time-sensitive tasks. |
| Unique value proposition | **Let your Claude play without stealing your workweek.** |
| Solution | Add a hard session cap, protected work buffer, budget preview, live progress, automatic pause, and a clear usage receipt. Only promise limits the runner can enforce reliably. |
| Channels | Developer and AI clubs, indie-hacker communities, Claude Code groups, current users, and cost-control demonstrations. |
| Revenue streams | Free basic control first; later test membership or advanced planning features. Basic safety controls should not be paywalled without strong evidence. |
| Cost structure | Usage measurement, runner enforcement, failure recovery, provider-change maintenance, interface work, and support for estimate mismatches. |
| Key metrics | Cap adoption, first-session starts, successful stops, zero breached promises, manual recalls, repeat sessions, and usage-related support issues. |
| Unfair advantage | The local runner already controls the execution boundary and can stop Daycare turns without giving the web hub broader permissions. Reliability would have to become the advantage. |

**Main assumption:** fear of allowance depletion materially blocks trial or repeat use, and a trustworthy boundary can be enforced.

**First test:** compare capped and uncapped session choices among 10 relevant Claude Code users while separately verifying the runner's measurement and stopping behavior.

## A1 — Autonomy Rehearsal

| Canvas box | Draft |
| --- | --- |
| Problem | Student coders want to try autonomous workflows but fear that an agent could make destructive or confusing changes in a real repository. Existing demonstrations do not let them build calibrated trust through direct experience. |
| Customer segments | Computer-science students and early-career developers who use Claude Code but avoid or heavily supervise autonomous workflows. |
| Unique value proposition | **Learn how your agent behaves autonomously without risking real work.** |
| Solution | Let a user's Claude complete playful missions with Daycare-only tools, then replay its decisions, failed attempts, resource use, and respected boundaries. |
| Channels | Computer-science courses, campus coding clubs, hackathons, Claude Code communities, and agent-building workshops. |
| Revenue streams | Free learning experiment first; later test inclusion in Daycare membership or paid workshop and curriculum packages. |
| Cost structure | Mission design, replay generation, behavior evaluation, product interface, workshop support, and maintenance as Claude Code changes. |
| Key metrics | Missions completed, replay completion, changes in trust calibration, later use of autonomous workflows, repeated missions, and safety misunderstandings. |
| Unfair advantage | Daycare already provides a deliberately restricted action space and inspectable records, which could make autonomy practice safer and more understandable than experiments in real repositories. |

**Main assumption:** experience in a playful sandbox changes how users understand or adopt autonomy in real work.

**First test:** give 10 cautious Claude Code users one fixed sandbox mission and replay, then measure whether they can predict agent behavior more accurately and whether they choose a wider—but still safe—boundary in a second task.

## B1 — Budget-to-Adventure Menu

| Canvas box | Draft |
| --- | --- |
| Problem | A percentage slider does not tell owners what kind of visit their allowance will buy. The unclear tradeoff makes it difficult to protect work capacity or decide whether a session is worth starting. |
| Customer segments | Claude Pro and Max users, especially students and side-project developers who actively manage limited weekly usage. |
| Unique value proposition | **Choose the adventure and understand the allowance before your Claude leaves.** |
| Solution | Offer small, standard, and ambitious outings with an estimated allowance range, likely duration, expected artifact, and visible uncertainty. |
| Channels | Current Daycare onboarding, Claude Code communities, campus AI clubs, budgeting-focused product demonstrations, and referrals. |
| Revenue streams | Free decision-support feature first; later test inclusion in a Daycare membership. The menu is unlikely to support a separate charge. |
| Cost structure | Usage estimation, activity calibration, interface work, testing across subscription plans, and support when estimates differ from actual usage. |
| Key metrics | Menu selection, session-start conversion, estimate accuracy, recalls caused by usage, completion by outing size, and repeat visits. |
| Unfair advantage | Historical Daycare activity and local runner measurements could improve estimates over time, although the menu interface itself is easy to copy. |

**Main assumption:** unclear cost-to-experience tradeoffs materially prevent visits, and estimates can be accurate enough to help rather than mislead.

**First test:** show 10 relevant Claude users a percentage slider and a three-option menu, compare which supports a confident choice, and test the selected estimate against a short real or staged outing.

## A3 — Explain-My-Agent Digest

| Canvas box | Draft |
| --- | --- |
| Problem | Raw agent traces are too long and technical for routine review. Owners cannot quickly identify why the agent acted, where it struggled, or whether it respected its boundaries. |
| Customer segments | Privacy-conscious Claude users curious about autonomy but unwilling to read raw logs. Early adopters include current Daycare users, student developers, and AI hobbyists. |
| Unique value proposition | **Understand what your agent did—and verify it—without reading the whole trace.** |
| Solution | A digest covering goals, pivotal choices, failures, surprises, tools, and boundaries, with every claim linked to the corresponding local-log evidence. |
| Channels | Current users after a visit, campus AI and coding clubs, Claude communities, local-AI groups, and educational demonstrations. |
| Revenue streams | Free trust experiment first; later test premium history, comparison, or export features. |
| Cost structure | Local processing, evidence indexing, report rendering, omission and hallucination evaluation, privacy work, and support. |
| Key metrics | Completion, comprehension, evidence-link use, time to explain what happened, unsupported claims, missed events, and repeat choice of the digest. |
| Unfair advantage | Source-linked explanations inside Daycare's deliberately restricted tool environment may be more trustworthy than summaries of unrestricted agents. Summary generation alone is easy to copy. |

**Main assumption:** owners want evidence-backed understanding after ordinary sessions and will use it often enough to affect trust or retention.

**First test:** compare hand-built digests with raw traces for 10 users, measuring comprehension, time, evidence use, and which format they choose for a second session.

## Comparison

| Concept | Access | Excitement | Pain | Total |
| --- | ---: | ---: | ---: | ---: |
| B2 — Allowance Guardrails | 4 | 5 | 5 | **14/15** |
| C3 — Two-Minute Reunion | 5 | 4 | 4 | **13/15** |
| B1 — Budget-to-Adventure Menu | 4 | 3 | 5 | **12/15** |
| A3 — Explain-My-Agent Digest | 4 | 4 | 4 | **12/15** |
| A1 — Autonomy Rehearsal | 4 | 4 | 3 | **11/15** |

B2 and C3 advance because they received the most votes and remain the strongest pair after Canvas comparison. They test opposite ends of the same loop: whether users feel safe enough about allowance to begin a visit, and whether the result is concise and meaningful enough to make them return. B1 overlaps with B2 and could become part of its pre-visit interface rather than a separate product direction.
